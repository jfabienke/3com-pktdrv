## 2. Performance position (emulator rig, Pentium 515dma100 timed cell)

| Metric | Start of 2026-07-12 | Now | Lever |
|---|---|---|---|
| 32K write | 331 KB/s, 96.6 ms/op (90% wait) | 1212 KB/s, 26.4 ms/op | #59 sync-point removal |
| 128K write | 1250 KB/s (QD1, unstable 2-3×) | 1888 KB/s (QD2, deterministic) | #51 pipelining |
| 32K read | 1684 KB/s | 1684 KB/s (unchanged, healthy) | — |
| Write vs read parity | 20% | ~110% (128K ops) | both |

**Residual walls (understood, not mysterious):**
1. **Protocol RTTs** — a write still pays cmd→R2T + data→Resp; QD=2 overlaps them across chunks;
   further gains need deeper QD or R2T elision (target-side `maxh2cdata`-covered first burst).
2. **Per-frame CPU on slow tiers** — per #64's measured rejection, the next slow-CPU lever is
   NOT ack elision; it's larger frames (/j, #26) or SACK-class RX, both parked.
3. **Rig physics** — wait components inflate with host load (3.5× within one boot); only
   matched-build same-boot A/Bs are valid; cpu-component is the stable cross-run signal.

## 4. Hardware-day runbook (#79)

Day one is measurement, not development:

1. **Bring-up:** `3cpd.exe /d` on the 905/905B; expect `armed RX Stage 2` + `caps` showing
   SG_TX(+HWCSUM on B). `sgtxtest.exe` proves gather+csum on real silicon (pcap on a mirror
   port or target-side capture).
2. **Corkscrew truth:** the 515 ladder step answers dn_writeback (R2 dual-evidence already
   hedges both ways) and real fragment-DMA fidelity (R3 risk).
3. **Latency decomposition:** `bench13h 0x82 s64 w p` — cpu/drv/wait per op with REAL RTTs.
   The #59/#51 sync-point count (2/op, overlapped) is the hardware-relevant metric; expect
   writes ≈ wire-bound.
4. **SG payoff check:** CFG_PROF PROF_COPY delta + throughput with/without the #31 wiring
   (implement from doc 14 §5.1 — estimated a day, all pieces proven).
5. **/j FDDI:** driver `/j` + `tcp_set_tx_mss_max` + Stage-2 large slots; the matrix gains its
   missing /j column.

## 6. Hard-won rules (do not relearn)

- **Measure before fixing; control for ordering.** #59's "slow after reads" framing was a
  matrix-ordering artifact; the write-first control disproved it in one boot.
- **Never delay ACKs on this stack** (#64): per-segment ACKs are the loss-recovery AND pacing
  mechanism (Go-Back-N + burst peers + 16-slot ring). Revisit only with SACK or a deep RX ring.
- **A flush-less sender needs a pumping receiver:** retransmit AND ring-tail transmission live
  only in `tcp_pump`; every receive wait must pump (tcp_read does now).
- **Matched-build, same-boot A/Bs only** — the rig's wait inflation swings 3.5× with host load.
- **Never pop a TxStatus you don't own; never AckIntr mid-drain on edge IRQs; descriptor memory
  is truth** (the ring-stall family, docs/12/13).
